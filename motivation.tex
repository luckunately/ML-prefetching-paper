\subsection{Motivation}
\textbf{WHAT MOTIVATES OUR WORK?}

Possible accessible virtual memory pages for a program is huge. It is normal for program to access several 10th of GBs of memory. Then that would be easy to get a billion of possible pages the program will access. It is hard to predict which page the program will access next and to prefetch it before the program access it.

Traditional prefetching techniques often rely on simple heuristics or patterns to predict the next memory page a program will access. However, with such large data sets, these methods frequently fall short, resulting in performance bottlenecks. The inability to accurately predict and prefetch the required memory pages in time can lead to increased latency and reduced overall application performance.

Improving the accuracy of prefetching is crucial for enhancing the performance and user experience of modern applications. By accurately predicting the next memory pages a program will access, we can reduce the number of page faults and ensure that the necessary data is available when needed. This not only improves the efficiency of the application but also provides a smoother and more responsive user experience.

\subsection{Information to be used for prefetching}

\textbf{WHAT INFORMATION CAN BE USED FOR PREFETCHING?}

There are lots of information that we can capture while a program is running. While collecting more information can help in predicting the next page the program will access, it can also increase the overhead of the prefetcher.

In this work, we will use the following information for prefetching:
\begin{enumerate}
    \item The virtual address of the page that caused the page fault.
    \item The program counter of the memory access instruction.
\end{enumerate}

These information are easily reachable and meaningful for prefetching.

Clearly, choosing the virtual address of the page and the program counter as the information for prefetching is strategic. These two pieces of information provide direct insight into the program's behavior without significant overhead. The virtual address of the page that caused the page fault indicates exactly which memory location the program is trying to access, while the program counter of the memory access instruction provides context about the specific operation being performed. Together, they offer a precise and low-overhead method to predict future memory accesses, making them ideal for an efficient prefetching mechanism.

\subsection{Prefetching as a classification problem}

Past work~\cite{LMAP} suggested that although page addresses are numbers, regression models are not suitable for prefetching. Instead, prefetching can be treated as a classification problem.

A simple analogy is to think of the page addresses as words in a large vocabulary. We can then treat the page addresses as discrete tokens and use classification techniques to predict the next page the program will access. Thus a wrong prediction is just simply a misclassification. No matter how far the prediction is from the actual page, it is still a misclassification.

Dealing with an enormous address space presents a significant challenge, as the number of possible pages that can be accessed is very large. This makes the encoding of the page addresses as one-hot vectors impractical due to its size. Additionally, fixed encoding of the page addresses can be problematic as address randomization can change the encoding of the page addresses.

Offsets provide a more efficient representation by mitigating the issues of absolute address encoding and address randomization. By using offsets, we can capture the relative changes in memory access patterns, which are more stable and predictable than absolute addresses.

To keep the model manageable and performant, it is necessary to filter out rare classes. Previous work~\cite{LMAP} has suggested that offsets of page address accesses work better than absolute addresses, and since we are doing classification, we need to filter out the rare classes and only leave up to 50,000 most occurred classes for offsets and pc values.

    {Offset} = {Next Page Address} - {Last Page address}
\end{definition}

The problem we want to solve is to predict the next page the program will access given the virtual address of the page that caused the page fault and the program counter of the memory access instruction. We will treat this problem as a classification problem and use offsets of the page addresses and program counter values as the classes.
